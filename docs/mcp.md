# MCP в Sculptor

Sculptor умеет принимать команды по Model Context Protocol: агент подключается
к запущенному редактору и правит то, что в нём открыто. План работ и принятые
решения — `docs/mcp-plan.md`; здесь то, что уже работает.

## Запуск и подключение

```
sculptor --mcp           # 127.0.0.1:17800
sculptor --mcp=18000     # другой порт
```

Без флага порт не открывается. Сервер попадает в бинарник при опции сборки
`VW_SCULPTOR_MCP` (по умолчанию `ON`); в сборке без него `--mcp` — ошибка
запуска.

Claude Code берёт адрес из `.mcp.json` в корне репозитория (`type: "http"`,
`http://127.0.0.1:17800/mcp`). Редактор должен быть запущен до подключения;
после перезапуска редактора достаточно переподключиться командой `/mcp` —
сеансов сервер не держит.

Состояние видно в правом углу строки меню: `MCP :17800 | N` — порт и число
принятых запросов, `MCP off` — сервер не слушает (причина в подсказке и в
логе).

**Порт занят — частый случай на Windows.** Система резервирует диапазоны
портов, и привязка к ним падает так же, как к занятому: на машине разработчика
закрытым оказался весь диапазон 47700–47899, хотя `netstat` и
`netsh int ipv4 show excludedportrange` его не показывали. Если сервер пишет
`port N is taken`, возьми другой порт флагом и поправь `.mcp.json`.

## Устройство

```
клиент ──HTTP POST /mcp──► сетевой поток: разбор HTTP, проверка Host и Origin
                                │ очередь (mutex + vector)
                                ▼
                app::update ── mcp_server::poll ── mcp_dispatcher ── инструмент
```

- **Сетевой поток** (`mcp/http_listener.cpp`) — единственное место с сокетами.
  Принимает соединение, читает один запрос, кладёт его в очередь и ждёт ответ
  от главного потока. Соединения обслуживаются по одному.
- **Главный поток** забирает очередь в `app::update`, то есть каждую итерацию
  цикла, в том числе при свёрнутом окне (`docs/ENGINE.md#главный-цикл`). Команда
  исполняется до шагов обслуживания состояния, и те в том же тике приводят
  документ в порядок.
- **Диспетчер** (`mcp/protocol.cpp`) разбирает JSON-RPC и зовёт инструмент.
  Сокетов и потоков он не знает.
- **Инструменты** (`mcp/editor_tools.cpp`) получают `mcp_bindings` — указатели
  на движок и состояние редактора.

Партиция — `vw.sculptor:mcp`. Наружу она отдаёт только `mcp_server`,
`mcp_bindings` и `default_mcp_port`; слушатель, диспетчер и описание
инструмента объявлены в том же `.cppm` вне `export`. При `VW_SCULPTOR_MCP=OFF`
вместо четырёх файлов `mcp/` собирается `mcp/server_disabled.cpp` с пустым
сервером.

## HTTP

Свой разбор, без библиотеки: задача — один локальный клиент.

| Запрос | Ответ |
|---|---|
| `POST /mcp` с `Content-Length` | ответ JSON-RPC, `application/json` |
| уведомление или ответ клиента | `202`, без тела |
| `GET`, `DELETE` на `/mcp` | `405`, `Allow: POST` |
| другой путь | `404` |
| `Host` или `Origin` не локальные | `403` |
| `Transfer-Encoding` в запросе | `411` |
| заголовки больше 16 КБ, тело больше 16 МБ | `431`, `413` |
| главный поток не ответил за 30 с | `504` |

- **Ответ всегда один и целиком.** Потока событий (SSE) нет, `GET` для него
  отклоняется — спецификация это разрешает.
- **`Connection: close` на каждый ответ.** Соединения не переиспользуются.
- **`Expect: 100-continue` поддержан:** его шлёт `curl` на телах больше
  килобайта.
- **Проверка `Host` и `Origin`** закрывает DNS rebinding: страница в браузере не
  может дотянуться до редактора, даже зная порт. Локальными считаются
  `127.0.0.1`, `localhost` и `[::1]`.
- Запрос, который не дождался ответа, помечается брошенным, и главный поток
  его не исполняет.

## Протокол

| Метод | Что делает |
|---|---|
| `initialize` | версия протокола, `capabilities.tools`, имя и версия сервера, краткая инструкция |
| `ping` | пустой результат |
| `tools/list` | имена, описания и схемы аргументов |
| `tools/call` | исполняет инструмент |
| `notifications/*` | принимаются без действия |

- Версия протокола: если клиент просит известную (`2025-11-25`, `2025-06-18`,
  `2025-03-26`, `2024-11-05`), сервер отвечает ею же, иначе `2025-06-18`.
- Пакеты (массив запросов) не принимаются: `-32600`.
- Сбой инструмента — не ошибка протокола: результат с `isError: true` и
  текстом, по которому агент может поправиться. Ошибкой JSON-RPC (`-32602`)
  отвечает только неизвестное имя инструмента или кривые `params`.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `editor_state` | открытый префаб, контекст правки и его стек, выбранный и редактируемый узел, клип, машина, несохранённые правки, возможность undo и redo, видно ли окно, занят ли редактор |
| `assets_list` | файлы, которые редактор может открыть: префабы, объёмы, клипы, машины |
| `palette_list` | все воксели каталога: индекс, имя, цвет, свечение и излучение; группы оттенков |
| `prefab_get` | открытый префаб: rig, машины и узлы с родителем, положением, поворотом в градусах, масштабом, объёмом и остальными компонентами |
| `prefab_new` | создать пустой префаб и открыть его |
| `prefab_open` | открыть префаб из каталога префабов |
| `prefab_save` | записать префаб и изменённые объёмы |
| `prefab_save_as` | сохранить под другим именем и продолжить в копии |
| `prefab_close` | закрыть префаб |
| `prefab_set_rig` | имя rig префаба |
| `node_create` | новый узел с размещением и компонентами |
| `node_delete` | удалить узел со всем поддеревом |
| `node_move` | сменить родителя или место среди соседей, сохранив мировое положение |
| `node_set_transform` | положение, поворот, масштаб; непереданные поля остаются |
| `node_set_components` | добавить, изменить или снять компоненты узла |
| `volume_get` | объём узла: размер, pivot, занятый бокс и воксели текстовыми слоями |
| `volume_write` | записать воксели: боксы, точки, слои |
| `volume_reshape` | изменить размер, обрезать, повернуть на четверти, отразить |
| `volume_set_pivot` | переставить pivot |
| `volume_rename` | переименовать файл объёма |
| `view_set` | навести камеру на узел или на весь префаб |
| `view_screenshot` | снимок вьюпорта картинкой |
| `undo`, `redo` | то же, что Ctrl+Z и Ctrl+Shift+Z |

Результат инструмента — один текстовый блок с компактным JSON;
`view_screenshot` кладёт перед ним блок-картинку (`image/png` в base64).

**Занятость.** `editor_state.busy` — причина, по которой редактор сейчас не
примет правку, либо `null`. Причин четыре: идёт размещение вставки, зажата
кнопка мыши (жест гизмо, выделение, полёт камеры), активно поле ввода или
ползунок, открыт диалог. Стартовый диалог занятостью не считается: агент сам
открывает префаб, и диалог после этого закрывается. Правящий инструмент
оборачивается в `when_idle` и при занятости отвечает отказом с этой причиной;
читающие инструменты работают всегда.

**Несохранённое.** `prefab_new`, `prefab_open` и `prefab_close` отказывают,
если есть несохранённые правки префаба, клипа или машины, и называют, чьи они.
Отбросить их можно только явным `discard_unsaved: true` — диалога «Discard?»
у агента нет.

**Имена префабов.** Имя принимается с `.vox` и без него; разделители пути и
символы, недопустимые в имени файла, отклоняются. `prefab_new` и
`prefab_save_as` не перезаписывают существующий файл без `overwrite: true`.

**Узел читается и пишется в одной форме.** `prefab_get` и ответы `node_*`
отдают узел теми же полями, какие принимают `node_create` и
`node_set_components`:

| Поле | Значение |
|---|---|
| `position`, `rotation_degrees`, `scale` | относительно родителя; поворот — эйлеровы углы в градусах |
| `volume` | `{"size": [x, y, z]}` — новый пустой объём, `{"ref": "models/….voxm"}` — файл; в ответе ещё `pivot` |
| `anim_target` | имя цели для клипов; `true` при записи берёт имя узла |
| `sockets` | список целиком: `name`, `position`, `rotation_degrees`, `scale` |
| `variant` | `candidates` (`.voxm` или `.vox`) и `selected` |
| `structure` | `type`, `races`, `tier` 0–5, `size` из `S`, `M`, `L`, `XL` |
| `furniture`, `connection` | категория и профиль точки |

В `node_set_components` трогаются только названные компоненты; `null` снимает
компонент. `sockets` и `structure` заменяются целиком, а не по полю.

**Один вызов — один шаг undo.** `node_create` со всеми компонентами и
`node_set_components` с несколькими компонентами исполняются одной составной
операцией: `undo` снимает всё разом.

**Проверка до исполнения.** Операции редактора ошибок не возвращают, поэтому
всё проверяет `node_service` до того, как собрать операцию: существование узла
и родителя, уникальность имени узла, цели и сокета, допустимость имени (буквы,
цифры, `_`, `-`, `.`), размер объёма (сторона 1–256), загружаемость файла
объёма, существование кандидатов варианта, цикл при переносе. Отказ ничего не
меняет и в историю не попадает. Единственное исключение — вариант: применимость
кандидата-префаба выясняется только при постановке, поэтому сервис исполняет
шаг, сверяет выбранный индекс и при неудаче сам делает undo.

**Неизвестное поле — ошибка.** `argument_reader::allow` отклоняет поле,
которого нет в схеме инструмента, и перечисляет допустимые. Опечатка в имени
поля иначе молча игнорировалась бы.

**Контекст.** Инструменты узлов работают в контексте префаба и сами в него
возвращаются: из объёма и машины — `ctx.leave_to(0)`, из клипа — через
`clip_service::exit_animation_mode`, который возвращает узлам позы покоя. Иначе
правка трансформа записала бы позу клипа.

### Объёмы

**Координаты.** Воксель адресуется целыми `[x, y, z]` от `[0, 0, 0]` до
`size − 1`; `y` — вверх. Начало координат узла лежит в `pivot` объёма, поэтому
воксель `[x, y, z]` стоит в узле в точке `[x, y, z] − pivot`.

**Слои.** `volume_get` отдаёт воксели текстом, и `volume_write` принимает его
обратно без переделки:

```json
"layers": {
  "origin": [0, 0, 0],
  "legend": {"a": "gray_5", "b": "red_2"},
  "slices": [["aaaa", "aaaa"], [".bb.", "...."]]
}
```

`slices[k]` — слой `y = origin.y + k`, его строка `j` — `z = origin.z + j`,
символ `i` строки — `x = origin.x + i`. `.` — воздух, остальные символы
расшифровывает `legend`: имя вокселя из `palette_list` или его индекс. При
чтении символы раздаются по убыванию частоты, поэтому `a` — самый частый
воксель региона. Без `min` и `max` читается занятый бокс; регион больше
40 000 ячеек не отдаётся, вместо слоёв приходит `truncated` с просьбой сузить.

**Запись.** Один вызов `volume_write` — один шаг undo. Сначала применяются
`boxes` (углы включительно), затем `points`, затем `layers`; позднее
перекрывает раннее. Воксель задаётся именем, индексом или `"air"`. В слоях `.`
стирает ячейку; с `"air": "keep"` оставляет её как есть — так накладывают
деталь поверх готового. Предел — два миллиона ячеек на вызов.

**Границы строгие.** Запись за пределы объёма — отказ, а не молчаливое
расширение: расширение в отрицательную сторону сдвигает все координаты, и
агент рисовал бы дальше по устаревшим. Объём растят явно —
`volume_reshape` с `resize`, — и ответ называет `shift`: на сколько сдвинулся
каждый воксель. После `rotate` и `mirror` координаты переставлены, и вместо
сдвига приходит `note` с просьбой перечитать объём.

**Общий объём.** Несколько узлов могут ссылаться на один файл `.voxm`; правка
через любой из них меняет все. `volume_get` перечисляет остальных держателей в
`shared_with`.

**Контекст.** Правящие инструменты объёма сами входят в контекст объёма узла —
в редакторе видно, какой объём правит агент, — а инструменты узлов возвращают
редактор в префаб.

### Вид

**Камера.** `view_set` ставит камеру редактора так, чтобы цель заполнила кадр:
цель — узел со всем поддеревом либо весь префаб, её центр и радиус берутся по
занятым вокселям в мировых координатах. Сторона задаётся именем (`from`) или
углами:

| `from` | Камера стоит | yaw, pitch |
|---|---|---|
| `iso` | со стороны +x +y +z | −135°, −30° |
| `+x`, `-x` | справа, слева | −90°, 90° |
| `+z`, `-z` | со стороны +z, −z | 180°, 0° |
| `+y`, `-y` | сверху, снизу | наклон ∓89° |

Направление взгляда — `(sin yaw · cos pitch, sin pitch, cos yaw · cos pitch)`,
как у `gfx::camera`. Гуманоид смотрит в +z: его лицо видно с `+z`. Камера
общая с пользователем: `view_set` двигает то, что он видит.

**Снимок.** `view_screenshot` отдаёт кадр таким, каким его рисует редактор, по
умолчанию без панелей и без оверлеев (оси, гизмо, рамка объёма); `interface` и
`overlays` их возвращают. `max_size` — длинная сторона картинки, по умолчанию
1024. На один кадр панели исчезают и у пользователя: снимается то, что ушло на
экран.

- **Снимок ждёт мешей.** Правка вокселей доходит до экрана не сразу: набор
  изменений поднимается на следующем обновлении мира, меш строит воркер. Снимок
  поэтому ждёт три тика и пустой очереди мешей
  (`renderer::has_pending_meshes`) и только потом заказывает кадр. Сценарий это
  стережёт: снимок сразу после `volume_write` отличается от снимка до него.
- **Ответ отложенный.** Инструмент не может ответить в том тике, в котором
  вызван: кадра ещё нет. Он возвращает `tool_outcome::later` — функцию, которую
  сервер зовёт каждый тик, пока та не отдаст результат; соединение всё это
  время ждёт. Так же должен быть устроен любой инструмент, чей ответ зависит от
  будущих кадров.
- **Свёрнутое окно — отказ.** Swapchain при этом нет, рисовать не во что.
  Остальные инструменты при свёрнутом окне работают.

Как снимается кадр — `docs/ENGINE.md#снятие-кадра`.

**Вещественные числа** в ответах пишутся кратчайшей записью исходного
`float32`: `0.99`, а не `0.9900000095367432`, которое дало бы прямое
расширение до `float64`. Делает это `json_of(float32)`; новые инструменты
отдают координаты и размеры только через `json_of`.

Рецепт нового инструмента — в навыке `sculptor`, раздел «MCP».

## Проверка

`python tools/mcp_smoke.py [--port=N] [--scenario]` — дымовой прогон по
запущенному редактору: рукопожатие, список инструментов, вызов, ошибки
протокола, отказы HTTP. С `--scenario` он ещё проходит инструменты префаба,
узлов и объёмов на временных префабах `_mcp_smoke*`, которые за собой удаляет:
открывает `p_humanoid`, сохраняет копию, собирает префаб из узлов с
компонентами, переносит, удаляет поддерево и сверяет, что undo вернул его в
точности, рисует объём боксами, точками и слоями, меняет его форму, правит
общий объём через второй узел и сверяет, что сохранённое читается с диска тем
же; наводит камеру и снимает кадр до и после правки. При свёрнутом окне
проверки снимка заменяются одной: снимок обязан отказать. Сценарий закрывает то, что открыто
в редакторе, поэтому на рабочей сессии его не запускают.

Автотестов у приложения нет, поэтому скрипт гоняется руками после правок в
`mcp/`, на видимом и на свёрнутом окне.
