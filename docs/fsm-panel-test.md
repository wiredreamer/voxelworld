# Ручная проверка панели машины состояний

Одноразовый лист: пройти панель State Machine руками и решить, что в ней
переделывать. После решения файл удаляется вместе с учебными ассетами.

## Подготовка

Учебные ассеты лежат в `assets/` и закоммичены вместе с этим листом:

- `prefabs/_fsm_playground.vox` — копия `p_humanoid`;
- `models/_fsm_playground/` — её объёмы;
- `fsm/_fsm_playground.voxf` — единственная машина префаба.

Машина: параметры `speed` (float), `grounded` (bool), `combo` (int), `attack`
(trigger); состояния `idle`, `walk`, `attack`; переход «из любого» в `idle`.
Боевые `humanoid_locomotion` и `humanoid_action` она не трогает.

Открыть: Prefab → Open → `_fsm_playground.vox`, выбрать `root` в Entity Tree,
в Entity Properties в блоке State machines нажать Edit.

Save в панели стоит нажимать только на шаге 21; до него исходный вид
возвращает Prefab → Close с отказом от изменений. Сохранённую правку
откатывает `git checkout -- assets/fsm/_fsm_playground.voxf`.

## Шаги

Каждый шаг — действие и то, что должно получиться. Расхождение — находка.

| № | Действие | Ожидание |
|---|---|---|
| 1 | Открыть машину, ничего не менять | Справа панель State Machine; в шапке путь `fsm/_fsm_playground.voxf` и слово `saved`; крошки показывают префаб и машину |
| 2 | Раскрыть `idle`, `walk`, `attack` | У каждого видны Name, Clip, Playback, Rate, Fade in, Fade out, переходы и строка incoming; у `idle` в заголовке `(entry)` |
| 3 | Изменить Rate у `walk` перетаскиванием | Пока тянешь — значение меняется; после отпускания в шапке `modified`; один Ctrl+Z возвращает прежнее число целиком |
| 4 | Ctrl+Shift+Z | Rate снова новый |
| 5 | Переименовать `walk` в `run` и нажать Enter | Переход `idle → walk` показывает `run`; строка incoming у `run` называет `idle` |
| 6 | Ctrl+Z после переименования | Имя и все переходы вернулись одним шагом |
| 7 | Сменить Entry на `walk` | `(entry)` переехало; один шаг undo |
| 8 | Add в Parameters | Появился параметр `parameter` типа float |
| 9 | Переименовать `speed` в `velocity` | **Подозрение:** условия `speed > 0` и `speed == 0` продолжат называть `speed` — переименование параметра по условиям не расходится |
| 10 | Сменить тип `grounded` с bool на float | Галочка сменилась на число; условие `grounded == true` в `walk` показывает `1.00` |
| 11 | Удалить параметр `attack` (кнопка `x`) | **Подозрение:** переходы с `on attack` останутся и будут ссылаться на несуществующий триггер; панель об этом не скажет |
| 12 | В переходе `idle → attack` стереть поле On | Переход теперь без триггера; заголовок перехода обновился |
| 13 | В поле On набрать `atack` с опечаткой | **Подозрение:** принимается молча — поле текстовое, списка триггеров нет |
| 14 | Add transition у `idle` | **Подозрение:** появляется переход с пустой целью; заголовок `->` без имени |
| 15 | Add condition в новом переходе | **Подозрение:** условие с пустым параметром и оператором `>` |
| 16 | В условии выбрать `combo` (int) и тянуть значение | Значение дробное, шаг 0,01 — для целого параметра это неудобно |
| 17 | Удалить состояние `attack` кнопкой Delete | **Подозрение:** переходы `idle → attack` и `walk → attack` останутся и будут вести в никуда |
| 18 | Add у States | Появилось `state_N`; раскрыть — Clip пустой, Playback loop, Rate 1 |
| 19 | В Clip набрать `animations/a_idle.voxa`, затем несуществующий путь | **Подозрение:** оба принимаются молча — выбора из файлов нет |
| 20 | Раскрыть сразу два состояния | Оба раскрыты; какое считается выбранным, из панели не видно |
| 21 | Save в шапке | `saved`; в `assets/fsm/_fsm_playground.voxf` изменения на месте |
| 22 | Ctrl+S, когда в машине есть несохранённое | **Известно:** сохраняется префаб, а не машина; `modified` остаётся |
| 23 | Выйти крошкой в префаб с несохранённой машиной, снова Edit | Правки на месте: та же машина с несохранённым не перечитывается |
| 24 | Prefab → Close при `modified` | Спрашивает про несохранённые изменения |

## Что видно по коду ещё до проверки

Панель — `apps/sculptor/src/ui/fsm_panel.cpp`, один поток виджетов без
промежуточной модели.

- **Проверки нет.** `asset::find_problems` уже умеет назвать всё из шагов 9,
  11, 13, 14, 15, 17 словами, но панель её не зовёт. Самое дешёвое улучшение —
  строка или список проблем в шапке.
- **Ссылки вводятся текстом.** Клип и триггер — поля ввода; цель перехода и
  параметр условия — уже списки. Клипу нужен выбор из файлов, триггеру — из
  параметров типа trigger.
- **Каскад есть только у имени состояния.** Переименование параметра и удаление
  состояния или параметра ссылки не чинят.
- **Порядок нельзя менять.** Переходы проверяются по порядку, а переставить их
  нечем — только удалить и создать заново.
- **Кривые не редактируются.** У затуханий и смешиваний правится только
  длительность; `interp` и тангенсы из файла сохраняются, но в панели их нет.
- **Значение условия — всегда число с шагом 0,01,** каким бы ни был тип
  параметра.
- **Ширина окна прибита** к 440 пикселям на каждом кадре.
- **Save не сообщает о неудаче:** результат `fsm_service::save` отбрасывается.
- **Проиграть машину нельзя.** Поставить параметр, дёрнуть триггер и увидеть,
  куда она перешла, можно только в арене.
