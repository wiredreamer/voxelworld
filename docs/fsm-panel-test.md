# Ручная проверка панели машины состояний

Одноразовый лист: пройти панель State Machine руками и решить, что в ней
переделывать дальше. После решения файл удаляется вместе с учебными ассетами.

Первый проход 02.10.2026 дал семь замечаний; панель по ним переделана, и лист
ниже описывает уже новую панель. Что изменилось — в конце.

## Подготовка

Учебные ассеты лежат в `assets/` и закоммичены вместе с этим листом:

- `prefabs/_fsm_playground.vox` — копия `p_humanoid`;
- `models/_fsm_playground/` — её объёмы;
- `fsm/_fsm_playground.voxf` — единственная машина префаба.

Машина: параметры `speed` (float), `grounded` (bool), `combo` (int), `attack`
(trigger); состояния `idle`, `walk`, `attack`; переход «из любого» в `idle`.
Боевые `humanoid_locomotion` и `humanoid_action` она не трогает.

Открыть: Prefab → Open → `_fsm_playground.vox`, выбрать `root` в Entity Tree,
в Entity Properties в блоке State machines нажать Edit.

Сохранённую правку откатывает `git checkout -- assets/fsm/_fsm_playground.voxf`.

## Шаги

Каждый шаг — действие и то, что должно получиться. Расхождение — находка.

| № | Действие | Ожидание |
|---|---|---|
| 1 | Открыть машину, ничего не менять | Справа панель State Machine; манипулятора на модели нет, щелчок по модели ничего не выделяет и не двигает; в крошках `_fsm_playground.voxf` без звёздочки |
| 2 | Раскрыть `idle`, `walk`, `attack` | У полей обычные подписи, нигде не видно `##…`; блоки разделены отступами; панель не выходит за окно, справа появляется прокрутка |
| 3 | Изменить Rate у `walk` перетаскиванием | После отпускания в крошках появляется `*`; один Ctrl+Z возвращает прежнее число целиком |
| 4 | Ctrl+S | Звёздочка в крошках пропала; в `assets/fsm/_fsm_playground.voxf` изменение на месте; префаб при этом не сохранялся |
| 5 | Переименовать `walk` в `run`, Enter | Переход `idle → walk` показывает `run`; строка Reached from у `run` называет `idle`; Ctrl+Z возвращает всё одним шагом |
| 6 | Clip у состояния | Выпадающий список файлов `animations/*.voxa` и `(none)`; опечататься негде |
| 7 | On trigger у перехода | Выпадающий список триггеров машины и `(none)` |
| 8 | Условие с параметром `grounded` | Значение — список `false` / `true`; с `combo` — целое, с `speed` — дробное |
| 9 | Run внизу панели | Слева появилось окно Machine Run: слой 0 в `idle`, клип `a_idle` идёт; модель дышит |
| 10 | В окне запуска поставить `speed` 1 | Слой 0 перешёл в `walk`, модель идёт |
| 11 | Нажать `attack` в окне запуска | Слой перешёл в `attack`, по окончании клипа вернулся |
| 12 | Не останавливая, изменить Rate у `walk` в панели | Ходьба сменила темп сразу; состояние осталось `walk`, `speed` остался 1 |
| 13 | Не останавливая, Add transition у `walk` и ничего в нём не выбирать | Машина продолжает идти; в окне запуска появилась строка, что правка не собирается и идёт последняя годная версия |
| 14 | Выбрать цель в новом переходе или удалить его | Строка в окне запуска пропала |
| 15 | Stop | Окно запуска закрылось, модель в позе покоя; префаб не помечен несохранённым |
| 16 | Run, затем выйти крошкой в префаб | Машины остановились, поза покоя вернулась |
| 17 | Prefab → Close при звёздочке у машины | Спрашивает про несохранённые изменения |

## Что ещё видно по коду

- **Проверки в панели нет.** `asset::find_problems` умеет назвать словами
  переход без цели, условие без параметра, повтор имени; панель показывает её
  ответ только когда машина запущена (шаг 13). Строка проблем в шапке — самое
  дешёвое следующее улучшение.
- **Каскад есть только у имени состояния.** Переименование параметра и удаление
  состояния или параметра ссылки не чинят.
- **Порядок переходов нельзя менять.** Проверяются они по порядку, а переставить
  нечем — только удалить и создать заново.
- **Кривые не редактируются.** У затуханий и смешиваний правится только
  длительность; `interp` и тангенсы из файла сохраняются, но в панели их нет.
