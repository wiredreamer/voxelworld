# Префабы: план

**Версия:** 1.4   **Дата:** 14 сентября 2026 г.   **Статус:** этапы 0, G, 1 и 2 сделаны

Движку не хватает переносимого описания составной сущности. Сегодня его роль
играет `vox_prefab_data` — дерево узлов с жёстко зашитым набором полей, где
воксели лежат прямо в файле дерева. Под вариативность (раса → варианты головы,
тела, рук) это не годится: вариант головы стоит копии всего персонажа.

План вводит семейство ассетов с одной точкой входа, открытый список компонентов
и явный контракт анимационного рига.

## Что решено

**Три слоя, а не один.** `model` — воксельный объём. `prefab` — дерево сущностей
с компонентами. Выбор конкретного варианта — свойство **экземпляра**, данные
спавна, а не файла. Отдельного игрового ассета (`creature_def`) не заводим:
префаб описывает слот и допустимых кандидатов, игра выбирает.

**Движок не знает игрового словаря.** `vw.asset` разбирает узел в property bag
(тег → значения) и не называет ни одного компонента. Смысл придаёт `vw.world`
через таблицу тегов. Граница, которую стережёт `scripts/lint_modules.py`,
сохраняется.

**Типы компонентов — compile-time, таблица тегов — рантайм.** Регистрация вида
`register_for<socket_component>("sockets", read, write, apply, phase)`: тип
известен, функции типобезопасны, рантайм — только диспетчер по строке из файла.
Плагины получаются бесплатно потом, но делаем не ради них.

**Отрисовка компонента — в Sculptor, не в движке.** ImGui линкуется PRIVATE
ровно в `vw.gfx` (`engine/gfx/CMakeLists.txt:84`), а компоненты живут в
`vw.world`, который собирается headless. Класть `draw_ui` рядом с компонентом
значит развернуть зависимость `world ← gfx` вспять. Две таблицы, связанные тегом.

**Точка вращения принадлежит модели, а не узлу.** Матрица собирается как
`T(position) · R · S · T(origin)` (`engine/core/src/math/math.cpp:623`), то есть
`origin` отвечает на вопрос «какая точка **геометрии** становится точкой
вращения узла». Это свойство объёма, а лежит оно сегодня в трансформе узла —
отсюда и жёстко прибитые `-6 -6 -6`, и ломающиеся при смене модели анимации.
`origin` переезжает в `.voxm` под именем `pivot`; узел хранит чистый трансформ
из position, rotation и scale.

**Риг — имя плюс сверка.** Имя рига (`humanoid`) пишется в шапку префаба, клипа
и FSM: дешёвая проверка, понятная ошибка, фильтрация списка клипов без чтения
файлов. Список целей не дублируем — он выводится из узлов с
`animation_target_component`, и сверка по нему остаётся настоящей проверкой.

**Sculptor — единый редактор.** Контекст редактирования — стек: провалился в
под-ассет, правишь его, вышел по крошкам. Architect из PRD — не второе
приложение, а тип документа плюс несколько компонентов.

## Форматы

| Расширение | Что | Ссылается на |
|---|---|---|
| `.vox` | префаб: дерево, компоненты, шапка с ригом | `.voxm`, `.voxf`, вложенные `.vox` |
| `.voxm` | воксельный объём: размер, набор блоков, воксели | — |
| `.voxa` | клип анимации (есть сегодня) | имена целей рига (строки) |
| `.voxf` | машина состояний: параметры, состояния, переходы | `.voxa` |

### Раскладка

```
assets/
  prefabs/     m_human.vox         дерево
  models/      m_human/body.voxm   объёмы, папка на префаб
  animations/  a_walk.voxa         клипы
  fsm/         humanoid.voxf       автоматы
```

Каталог на тип, а не папка на персонажа: клип и автомат пишутся под риг, а не
под префаб, и один `a_walk.voxa` обслуживает всех гуманоидов — сложи их по
персонажам, и общий клип придётся дублировать. Объёмы, наоборот, принадлежат
одному префабу, поэтому у них папка по его имени.

Имена каталогов лежат в `vw::asset::dirs`, а не строками по приложениям: по ним
движок строит ссылку безымянного объёма (`models/<префаб>/<узел>.voxm`), и по
ним же Sculptor показывает списки. Разойдись эти два места — редактор написал бы
ссылку, по которой игра ничего не найдёт.

Префаб **не перечисляет клипы** — он ссылается на FSM, клипы тянет она. Иначе
список живёт в двух местах и разъезжается.

FSM в префабе — **список**, по одной на слой: `animation_fsm_component` уже
держит `std::vector<animation_fsm>`, и arena этим пользуется (слой 0 —
локомоция, слой 1 — атака).

Ссылка — тип `asset_ref`, **всегда от корня ассетов**, никогда относительно
файла. Тогда перетасовка папок — правка ссылок, а не смена формата: раскладка
остаётся вопросом удобства (см. «Раскладка»).

Битая ссылка не рвёт загрузку: заглушка вместо модели, узел красным в дереве,
одно сообщение в лог. Прецедент есть — неизвестный блок рисуется заглушкой
кричащего цвета.

### Пример `.vox`

```
# vox 3.0
kind character
rig humanoid
entity root
	transform -6 -6 -6	0 0 0	1 1 1
entity body
	parent root
	transform 0 0 0	0 0 0	1 1 1
	model models/m_human/body.voxm
	anim_target body
entity hand_right
	parent body
	sockets
		socket hand_right	0.5 0 0	0 0 0	1 1 1
fsm fsm/humanoid_locomotion.voxf fsm/humanoid_action.voxf
```

Синтаксис узла — «тег плюс свойства» с самого начала, даже пока их читает
фиксированный код. Иначе формат придётся менять дважды.

### Пример `.voxm`

```
# voxm 1.0
encoding rle
category creature
size 14 12 12
pivot 7.5 6.5 5.5
r 3 0 0 9 51
r 3 1 0 1 51
r 4 1 0 7 52
```

Пробег `r x y z count index`: набор у модели один, поэтому пишется только номер
в наборе, а не `категория:номер` на каждый воксель. `encoding` в шапке — чтобы
`binary` добавился позже без смены расширения и версии.

Имя модели — из имени файла, не изнутри. Заложить поле под хеш содержимого.

`pivot` — точка **в координатах вокселей этой модели**, которая совмещается с
началом координат узла; знак противоположен сегодняшнему `origin`, потому что в
матрицу он входит как `T(-pivot)`. Дробные значения законны и нужны: у `body`
это `7.5 6.5 5.5` при объёме 14×12×12 — не центр, а анатомическая точка.

### Пример `.voxf`

```
# voxf 1.0
rig humanoid
param speed float 0
param grounded bool true
param jump_count int 0
param attack trigger
layer 0 locomotion
	state idle	clip anims/idle.voxa	loop
		to walk	when speed > 0.1	blend 0.25
		to jump	when grounded is false	blend 0.15
	state walk	clip anims/walk.voxa	loop
		to idle	when speed <= 0.1	blend 0.25
layer 1 action
	state attack	clip anims/attack.voxa	once
		from any	on attack	blend 0.15
```

Условие — тройка `{параметр, оператор, значение}`, у перехода список через AND.
OR не нужен: это второй переход в ту же цель. Языка выражений со скобками нет.

Параметры: `bool`, `float32`, `int32`, `trigger`. Имена резолвятся в индексы один
раз при загрузке — FSM считается каждый кадр на каждом существе, строковому хешу
там не место.

Кто пишет параметры: **движок** поставляет встроенные из компонентов, которые и
так знает (`speed_xz`, `velocity_y`, `grounded` из `rigid_body_component` и
`movement_intent_component`); **игра** пишет своё явно
(`set_int("jump_count", n)` — ровно случай `jump_counter_` из `player`).
Декларативной привязки вида `param speed from rigid_body.velocity` не делаем:
она требует рефлексии, которой нет, и вырождается во второй язык выражений.

`wait_until_end` / `wait_until_blend` остаются флагами — это условия на состояние
проигрывателя, а не на данные.

## Этапы

### 0. Мины — S — **сделано**

Чинится независимо от всего остального, разблокирует спокойную работу дальше.

- `model_registry::create` молча перетирал модель по имени, а имя = имя
  сущности: два узла `head` из разных префабов дают одну запись. Сегодня это
  безвредно — `get`/`has` не зовёт никто, модель держит компонент, — но на
  этапе 1 `asset_storage` начнёт дедуплицировать модели через `get`, и запись
  станет рабочей. Пока перезапись просто громко логируется; настоящее
  исправление — ключ-путь вместо имени узла — часть этапа 1.
- Родитель обязан был идти по файлу раньше ребёнка, иначе связь терялась без
  ошибки. Сделаны два прохода: сперва заводятся все узлы, потом связывается
  иерархия. Ненайденный родитель больше не молчит.
- Версия файла не читалась — `# Vox File Version 2.0` был просто комментарием.
  Теперь разбирается и сверяется по старшему номеру, у `.vox` и `.voxa`
  одинаково; константа `vox_file_version` переехала из `vw.world` в `vw.asset`,
  к разборщику. Политика: чужой старший номер — отказ с `unsupported_version`,
  младший — читается, версии нет — читается, неизвестный тег — warning и пропуск.
- Побочно разведены разбор и применение: `vox_deserializer::instantiate`
  принимает готовый `vox_prefab_data`. Это же понадобится на этапе 5 для
  подстановки варианта.

**Проверка:** `asset_tests`, `world_tests`.

**Приёмка:** `m_human.vox` открывается, в дереве все семь узлов, персонаж
выглядит как раньше. Файл, где ребёнок объявлен раньше родителя, собирается в
правильную иерархию. Файл с неизвестной версией в шапке даёт внятный отказ, а
файл с неизвестным тегом внутри — открывается с предупреждением в логе.

### G. Gizmo — L — **сделано**

Независим от остального плана: форматов не трогает, может идти хоть первым.
Единственный этап, который добавляет код в `vw.gfx`, а не только в Sculptor.
Польза немедленная — сегодня поза для кейфрейма набирается числами в полях.

- Инструмент `gizmo_tool` поверх `base_tool`: перемещение, вращение, масштаб;
  режимы переключаются клавишами.

**Залитые debug-примитивы — новая работа в `vw.gfx`.** Сегодня отладочная
геометрия умеет только линии: `debug_primitives` копит один буфер
`debug_vertex{pos, color}`, а `debug_pipeline_` собран с `eLineList`
(`renderer.cpp:1050`). Gizmo из линий выглядит проволокой и не читается.

Нужен второй пайплайн, отличающийся от существующего четырьмя полями:

- `eTriangleList` вместо `eLineList`;
- `depthTestEnable = False` — ручка, утонувшая в модели, обязана оставаться
  доступной, иначе до неё не дотянуться (существующий пайплайн тестирует глубину
  через `eGreater`, у нас reversed-Z);
- `blendEnable = True` — квадраты двухосевого перемещения полупрозрачны;
- `cullMode = eNone` — на gizmo смотрят с любой стороны.

Шейдеры переиспользуются как есть: `debug.vert/frag` принимают позицию и
упакованный цвет и уже распаковывают альфу. В `renderer` добавляется приём
треугольников и второй буфер; сами фигуры (конус, цилиндр, кольцо, квадрат)
строит Sculptor — если они понадобятся и в arena, поднимутся в движок потом.

**Хит-тест идёт не по этой геометрии, а по аналитике.** Объём нужен глазу, а
попадание от него только проиграет: конус стрелки тонкий, кольцо вращения —
тонкая лента, и по мешу в них не попасть. Вместо этого — ось как отрезок с
допуском, заданным **в экранных пикселях** и переведённым в мир через расстояние
до камеры; кольцо как луч против плоскости с проверкой `|r - R| < допуск`;
квадрат как луч против плоскости с попаданием в границы. Всё это уже есть в
`vw::spatial`, а луч даёт `camera.screen_to_world_ray` — ровно как в
`select_entity_tool`. Заодно попадание перестаёт зависеть от тесселяции.

- Приоритет при перекрытии задать явно: квадраты плоскостей выше осей, ближняя
  ручка выше дальней. У центра gizmo сходится всё, и без порядка клик там будет
  выбирать случайную ось.
- **Одна операция undo на жест.** На нажатии запоминается исходный трансформ, на
  отпускании создаётся `set_transform_operation` с парой «было / стало»; между
  ними трансформ меняется напрямую, мимо `operation_manager`. Иначе Ctrl+Z будет
  откатывать по кадру перетаскивания.
- Постоянный экранный размер — масштаб от расстояния до камеры, иначе на
  отдалённой камере в ось не попасть.
- Снап включён по умолчанию (полвокселя, 15°, 0.1 масштаба), `Ctrl` отключает.
  Для воксельной сетки это правильная сторона по умолчанию, в отличие от
  универсальных редакторов.
- Пространство local и world с переключателем. Анимации нужен local: руку
  вращают вокруг её собственного плеча.
- В анимационном контексте gizmo правит позу, а запись кейфрейма остаётся
  отдельным действием. Но если кейфрейм на текущем времени уже существует — он
  обновляется через `modify_keyframe_operation`, а не дублируется.

ImGuizmo не берём: он тянет зависимость ради одной фичи, рисует через ImGui
поверх кадра и не покрывает главный для нас случай — маркер pivot со снапом на
воксельную сетку. Пикинг у нас свой, а залитые примитивы нужны в движке
независимо от gizmo: ими же рисуются маркеры сокетов и рамки занятого объёма.

**Приёмка:** руку персонажа можно повернуть мышью, и повёрнутая поза совпадает с
тем, что показывают поля вектора. Одно перетаскивание отменяется одним Ctrl+Z и
возвращается одним Ctrl+Shift+Z. Со снапом вращение встаёт кратно 15°, с зажатым
Ctrl — плавно. Отдалив камеру втрое, в ось по-прежнему попадаешь — допуск
пиксельный, не мировой. Ручка, оказавшаяся внутри модели, остаётся видимой и
кликабельной. Клик у самого центра gizmo стабильно выбирает одну и ту же ручку,
а не случайную. Кейфрейм, записанный после жеста, воспроизводится ровно той
позой, которую поставили.

### 1. Разделение объёма и дерева — L — **сделано**

Сердце плана. Всё остальное от него зависит.

- Новая партиция `vw.asset:serial.voxm` — писатель и разборщик объёма.
- `vox_entity_data`: `std::optional<vox_model_data> model` → `asset_ref model`.
  Формат узлов сразу переводится на «тег плюс свойства».
- `asset_storage` грузит модели по ссылке с дедупликацией по пути.
- `vox_serializer` / `vox_deserializer` пишут и читают ссылку.
- **`origin` уезжает из `transform` в `pivot` модели.** `vw::transform` теряет
  четвёртое поле, `calc_matrix` берёт pivot у модели узла. Логика компенсации
  при расширении объёма уже написана и просто переезжает внутрь модели
  (`expand_model_operation.cpp:64-71`: `new_origin = origin - zeroed_dir`).
- **`animation_property::origin` удаляется.** Клип не должен знать геометрию:
  сегодня он её знает, и потому правка модели ломает все кейфреймы. Ассеты это
  переживут без потерь — в пяти клипах `channel origin` объявлен 26 раз и не
  содержит **ни одного** кейфрейма, а фолбэк на rest уже написан
  (`animation_system.cpp:685`).
- Миграция узлов без модели: у такого узла `T(p)·R·S·T(o)` при единичных `R` и
  `S` равно `T(p+o)`, то есть origin сворачивается в position. В сегодняшних
  ассетах такой узел ровно один — `root` у `m_human` (7 узлов, 6 моделей) — и
  условие выполняется. Конвертер обязан проверять его, а не предполагать.
- `file_service::save` пишет префаб плюс **только грязные** модели;
  `file_state::has_unsaved_changes` превращается в множество. Иначе каждый
  Ctrl+S перезаписывает все `.voxm` и шумит в git.
- Миграция: чтение старого формата (v2.0) временно остаётся, запись — только
  новая (v3.0). Шесть файлов конвертируются открытием и сохранением, после чего
  чтение v2 удаляется. Надёжнее отдельного скрипта.

**Что получилось.** Ссылка — тип `asset_ref`: путь от корня ассетов, с
нормализацией написания, потому что она же служит ключом кеша. Корень знает
приложение — у редактора это его рабочий каталог, у игры папка `assets` рядом с
исполняемым файлом, — и `model_library` держит пару «корень плюс кеш по ссылке».
Ею же закрыта мина №1 этапа 0: ключом стал путь, а не имя узла.

Теги узла переименованы под «тег плюс свойства»: `t` → `transform` (девять
чисел, без origin), `m` → `model <ссылка>`, `target` → `anim_target`. Разные
теги у разных версий оказались удобны: одному разборщику не нужно ветвиться по
шапке, он различает версии по самим строкам, а шапка только решает, отказываться
ли. Поля `legacy_model` и `legacy_origin` в `vox_entity_data` помечены как то,
что уедет вместе с чтением 2.0.

Грязные модели считаются не по операциям, а по `changed<model_component>` в
кадре редактора. Дописывать список в каждой новой операции пришлось бы вечно, и
первая же забытая молча потеряла бы правку; общий признак изменения ловит и
undo, и инструменты, и то, что появится потом. После открытия документа грязными
оказываются все его объёмы — это ровно то, что нужно для конвертации.

**Как переведены ассеты.** Не открытием и сохранением, как планировалось, а
разовым конвертером на самом движке: он читал 2.0, писал 3.0 плюс `.voxm`, а
потом **перечитывал написанное с диска** и сверял с исходным — дерево, узлы,
сокеты, размер, точку вращения и каждый воксель, включая пустые. Шесть файлов,
ноль расхождений. Ручное сохранение проверило бы ровно то же самое, но глазами и
без сверки по вокселям, а конвертер после работы удалён.

Чтение 2.0 убрано сразу следом: поля `legacy_*`, `vox_model_data`, теги
`t`/`m`/`v`/`target` и разбор идентификатора блока в дереве. Файл 2.0 теперь
отвергается по версии — это важнее, чем кажется: без проверки версии каждая его
строка ушла бы в «неизвестную команду», и документ открылся бы пустым вместо
внятного отказа.

Побочно `vox_parser_plain` перестал зависеть от каталога блоков — он больше не
читает вокселей. Предупреждение о блоке вне каталога переехало в
`voxm_deserializer`, туда же, где теперь лежат воксели; терять его было нельзя,
это единственный сигнал о том, что модель нарисуется заглушкой.

Запрет на смешение наборов в одной модели проверять больше нечем и незачем:
в `.voxm` набор стоит в шапке один раз, и файл из двух наборов не представим.

`m_human` ужался с 43 955 до 17 595 байт на всё семейство — в 2,5 раза, а не в
пять-десять, как прикидывалось: пробеги по X хорошо жмут ряды одного блока, но у
персонажа таких рядов меньше, чем у рельефа. На всех шести ассетах 57 559 байт
против 26 434. Единственный, кто вырос, — `m_arrow` (507 → 583): у объёма из
пары десятков вокселей шапка `.voxm` дороже самих пробегов.

Единственная шероховатость: у префаба с одной моделью на корне объём ложится в
`models/m_sword/root.voxm`. Правило имени одно на конвертацию и на запись
редактора, и разводить их ради пяти файлов дороже, чем стерпеть лишнюю папку.

**Ломается:** все существующие `.vox`.
**Проверка:** round-trip тест в `tests/asset/` (записал → прочитал → сравнил) —
он же ловит рассинхрон писателя и парсера, которые лежат в разных модулях и
сегодня расходятся молча.

**Приёмка:** открыть `m_human.vox` — персонаж выглядит как раньше, руки и голова
на своих местах (это проверка переезда pivot). Поправить один воксель в кисти и
сохранить — `git status` показывает изменённым **один** `.voxm`, префаб и пять
остальных моделей не тронуты. Запустить arena: персонаж на месте, меч цепляется к
руке, ходьба и атака проигрываются как раньше.

### 2. Риг и шапка префаба — S — **сделано**

- Шапка: `version`, `kind` (character / structure), `rig <name>`.
- `rig_component` на корне несёт имя — сериализация и инспектор достаются даром
  из общей таблицы (этап 4), новой сущности не заводим.
- Сверка целей при загрузке клипа и FSM: ругаться внятно, а не молча не
  анимировать.
- Панель Rig в Sculptor — плоский список целей документа. Timeline уже показывает
  примерно это, вид переиспользуется.

**Что сделано.** `rig <name>` — строка в шапке `.vox` (3.1) и `.voxa` (1.1);
обе необязательные, поэтому младший номер, и файл без рига читается как «риг не
указан». В мире имя несёт `rig_component` на корне, сверка — `check_clip` на
`animation_system`, список целей — `collect_targets` там же.

Сверка двухслойная, и оба слоя нужны. Имя рига отвечает на вопрос «этот клип
вообще про это существо?» и стоит одно сравнение строк. Настоящая проверка идёт
по целям: имена совпали, а узла для дорожки нет — клип всё равно наполовину
немой. Пустое имя с любой стороны — «не указан», а не «не совпало»: клип, снятый
до этой проверки, ни в чём не виноват.

Отдельно закрыт самый дорогой вид молчания: дорожка без узла не давала ни
ошибки, ни лога — она просто ничего не двигала
(`animation_system.cpp`, финальная запись поз пропускала имя, которого нет в
карте целей). Теперь `animation_system` ругается при привязке клипа к плееру, по
одному разу на имя и на корень: в покадровом применении логу не место, а раз в
переход — в самый раз.

**Чего нет.** `kind` (character / structure) не сделан. Его сегодня некому
читать, а из шести префабов пять — предметы: меч не character и не structure,
и писать в файл ответ, в который сами не верим, хуже, чем не писать ничего.
Строка добавляется в шапку без смены версии, когда у неё появится потребитель —
Architect (этап 7).

**Проверка:** `world_tests` на сверку целей — `tests/world/rig.test.cpp`
(шесть случаев) плюс round-trip рига в `scene_serial.test.cpp`.

**Приёмка:** панель Rig показывает шесть целей `m_human`. Клип, записанный для
другого рига, при открытии даёт сообщение с обоими именами, а не молчит и не
падает. Клип своего рига открывается и играет.

### 3. Контексты в Sculptor — M

- `edit_context` — **стек** значений (тип, `asset_ref`, область правки), не enum:
  из `.voxf` надо уметь провалиться в клип состояния.
- Область правки — поле контекста: у `.voxm` один узел, у `.voxa` все узлы рига,
  у `.voxf` ни одного.
- Крошки: `m_human.vox › head.voxm`, `m_human.vox › walk.voxa`.
- Инструменты по контексту: воксельные только внутри `.voxm`, `select_entity` —
  только в префабе.
- `animation_state::animation_mode` умирает: read-only дерева в анимации
  становится следствием общего правила, а не проверкой в каждой панели
  (`entity_tree_panel.cpp:43` и далее).
- Undo: стек общий, **операция хранит путь контекста**, undo переключает контекст
  прежде чем откатить. Иначе Ctrl+Z меняет невидимое.
- На входе в контекст под-ассета — пометка «используется в N префабах». Для
  клипов особенно: они общие по замыслу.
- В контексте `.voxm` — видимый маркер `pivot`, который двигается тем же gizmo со
  снапом в полвокселя. Сегодня точка вращения правится только косвенно, через
  расширение объёма, и поставить её осознанно нельзя вообще.
- Рядом с габаритом модели рисуется **фактически занятый объём** — рамка по
  непустым вокселям. После расширения модель часто болтается внутри собственного
  объёма, и по одному габариту не видно, что pivot стоит не в геометрии, а в
  пустоте.
- Операция `trim_model_operation`: обрезать пустые слои с краёв с компенсацией
  pivot. Обратной к `expand_model_operation` сегодня нет, поэтому пустые слои
  копятся и портят и точку вращения, и память под страницы.

**Ломается:** UI-код, завязанный на `animation_mode`.
**Проверка:** `world_tests` на trim с компенсацией pivot.

**Приёмка:** двойной клик по узлу проваливает в модель, крошки показывают путь,
воксельные инструменты доступны только внутри. Правка вокселя, выход наверх,
Ctrl+Z — контекст сам возвращается в модель и откатывает правку там, где её
видно. В анимационном контексте дерево не даёт добавить узел. Расширить модель
на слой, зайти в неё: рамка занятого объёма видимо меньше габарита, маркер pivot
стоит в пустоте; `trim` возвращает их в совпадение, а персонаж при этом не
сдвигается.

### 4. Таблица компонентов — M

- Property bag в `vw.asset`: узел = имя, родитель, трансформ и список
  `{тег → {ключ → variant<bool, int32, float32, vec3f, quat, string>}}`.
  Узлов в дереве десятки, не миллионы — воксели сюда после этапа 1 не попадают.
- Реестр в `vw.world`: `register_for<T>(tag, read, write, apply, phase)`.
  `read` и `write` регистрируются **парой** — сегодня они в разных модулях.
- **Фазы применения обязательны и явны**: hierarchy → transform → остальное.
  Сегодня порядок зашит в `apply_entity_` и важен (animation target читает rest
  из уже выставленного трансформа); с таблицей он иначе станет порядком
  регистрации, то есть случайностью.
- Переезд существующих: `model`, `sockets`, `anim_target`.
- Реестр отрисовки в Sculptor: тег → `draw`. Инспектор обходит его вместо
  статического списка из трёх пунктов (`entity_properties_panel.cpp:175-239`).

**Проверка:** `world_tests` на порядок фаз и на round-trip узла со всеми тегами.

**Приёмка:** зарегистрировать пробный компонент из двух полей одной строкой — он
сам появляется в инспекторе, правится там, сохраняется в `.vox` и читается
обратно, без единой правки в парсере, писателе и панели свойств. Существующие
`m_human` и `m_sword` после переезда `model`/`sockets`/`anim_target` на таблицу
открываются и сохраняются побайтово одинаково.

### 5. Слоты вариантов — M

- `variant_slot_component`: имя слота, список кандидатов, контракт (какие цели
  рига и какие сокеты кандидат обязан закрывать).
- Кандидат — `asset_ref` без поля типа: `.voxm` подменяет модель узла, `.vox`
  подставляет поддерево, тип определяется расширением. Простой случай не платит
  за сложный.
- Узел-ссылка на внешний `.vox` — легализация превью сокетов
  (`socket_panel.cpp:338`): сегодня чужой ассет грузится в мир и исключается из
  записи через `options.excluded`. Механизм остаётся, но исключает «содержимое по
  ссылке», а не «превью».

**Проверка:** `world_tests` — подстановка кандидата, не закрывающего контракт,
отклоняется внятно.

**Приёмка:** сделать две головы разного размера, собрать из них слот, переключать
в инспекторе — голова меняется, **шея и шлем на сокете не едут** (это главная
проверка того, что pivot живёт в модели). Ходьба продолжает играть при любом
выбранном варианте. Кандидат без нужной цели рига в слот не встаёт и говорит,
чего ему не хватает.

### 6. FSM — L

- Формат `.voxf` и его разборщик.
- `animation_fsm::condition_fn` → условия по параметрам; blackboard плоским
  массивом в `animation_fsm_component` рядом с `triggers_`.
- Встроенные параметры заполняет `animation_fsm_system` перед оценкой.
- Переходы `from any` — нужны уже сейчас (атака из любого состояния).
- `setup_animation_fsm()` из `apps/arena/src/app/player.cpp` уезжает в файл
  целиком, кроме триггера `attack`. Это и есть проверка схемы.
- **Окно состояния — debug-окно `vw.gfx`**, а не панель Sculptor: отлаживать FSM
  надо в игре, где параметры настоящие. Данные для него уже лежат в
  `animation_layer` — `fade_influence`, `blend_elapsed`, `blend_transition`,
  `mask`; нужен только вид.
- Контекст `.voxf` в Sculptor — плоский список в три уровня (слой → состояние →
  переход) плюс вычисляемая секция «входящие». Графового редактора нет: граф
  циклический, дерево его не выражает, а список даёт даром то, чего граф не
  даёт — ответ на вопрос «кто сюда ведёт».

**Проверка:** `asset_tests` на разбор `.voxf` и на вычисление условий.

**Приёмка:** arena ведёт себя неотличимо от сегодняшней — ходьба, двойной прыжок,
атака с мечом, смешивание слоёв. Окно состояния по `CTRL+F12` показывает активное
состояние каждого слоя, значения параметров и идущий переход с его прогрессом.
Правка `blend` в `.voxf` и перезапуск меняют ощущение перехода, не трогая код.
`setup_animation_fsm()` из `player.cpp` удалён.

- Метаданные из PRD (`docs/PRD.md:429`) — обычные компоненты: `type`, `race`,

## Чего сознательно не делаем

- **Наследование префабов** (prefab variant: база плюс дельта). Мощно и дорого —
  и в реализации, и в отладке, когда непонятно, откуда взялось значение.
- **Отдельный игровой ассет `creature_def`.** Его роль сводится к набору выборов,
  а выбор — свойство экземпляра.
- **Бинарный `.voxm` сейчас.** Поле `encoding` оставляет дверь открытой; текст с
  пробегами ужмёт `m_human` раз в пять-десять от нынешних 43 КБ, и этого хватит
  надолго.
- **Графовый редактор FSM.** Сначала формат и окно состояния; на пяти-пятнадцати
  состояниях список не хуже графа.
- **Декларативная привязка параметров FSM к полям компонентов.**
- **Перекраска через ремап палитры.** Разделы набора (`skin`, `cloth`, `metal` —
  диапазоны подряд) делают цветовые варианты почти бесплатными по памяти, но
  мешер сливает грани по совпадению блока, а палитра на устройстве адресуется
  `block_slot`. Нужен отдельный разбор; пока цветовой вариант — отдельный
  `.voxm`.

## Порядок и зацепления

Этапы 0 и G независимы от всего и друг от друга; G стоит делать раньше прочего —
он ничего не ломает, а перетаскивать мышью вместо набора чисел хочется уже
сейчас. Дальше строго: 1 → 2 → 3, причём 4 можно вести параллельно 3 (разные
файлы), а 5 и 6 требуют 4 и 2 соответственно. 7 — после 4. Маркер pivot из этапа
3 опирается на G.

Приёмка у каждого этапа — сценарий руками в Sculptor или arena, а не только
зелёные тесты. Тесты ловят регрессию в разборе и в данных; то, что редактор
стал неудобен или персонаж поехал на полвокселя, видно только глазами.

Sculptor остаётся рабочим после каждого этапа. Порядок не переставляется:
контексты без разделения форматов бессмысленны, слоты без таблицы упрутся в тот
же статический список.
